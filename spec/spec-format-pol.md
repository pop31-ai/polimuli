# POL — Полиарт-Разметка Эпизода (Poly Animation Language)

Формат данных **`.pol`** — единый способ описать полиарт-эпизод так, чтобы
его мог проиграть любой плеер и упаковать любой упаковщик. Это «поли» в
трёх смыслах:

- **поли-эпизод** — формат охватывает все 65+ мультов каталога, не привязываясь
  к конкретному мульту;
- **поли-язык** — эмодзи — первые классы данных: персонаж, частица, значок
  фона — это просто словарь эмодзи (как и всё в полиарт-направлении);
- **поли-каналы** — один файл `.pol` играется в браузере, в приложении,
  печатается в «сценарный лист» или переупаковывается в автономный HTML.

Формат — это **только данные**: никаких функций, объектов кода или
исполняемых выражений. Безопасность и простота — приоритет.

**Статус.** POL — личный (авторский) формат проекта polimuli. Схема
версионируется в этом репозитории; при необходимости формат может быть
открыт сообществу или отдан под управление (стандартизирован).

- Расширение файла: `.pol`
- MIME-маркер: `polimuli/pol`
- Версия схемы: `1`

---

## 1. Минимальный пример

```json
{
  "format": "polimuli/pol",
  "version": 1,
  "meta": {
    "id": "16",
    "title": "Экспресс «Стрела»",
    "genre": "дорога-приключение",
    "dur": 24
  },
  "canvas": { "w": 960, "h": 540 },
  "acts": [
    { "at": 0,  "text": "ПОЕЗД ГОТОВ К РЕЙСУ", "bg": { "top": "#2b2f45", "bottom": "#12141c" } },
    { "at": 6,  "text": "ВЫЕЗЖАЕМ!",             "bg": { "top": "#3a4a63", "bottom": "#1a2030" } }
  ],
  "actors": [
    { "id": "train", "emoji": "🚂", "x": 180, "y": 300, "size": 90,
      "bob": { "amp": 8, "speed": 1.4 },
      "key": [ { "at": 0, "x": 180 }, { "at": 6, "x": 820 } ] }
  ],
  "particles": [
    { "from": "train", "dx": -30, "dy": -20, "emoji": "💨", "rate": 0.08,
      "vx": 0, "vy": -40, "life": 0.7, "size": 18 }
  ]
}
```

## 2. Корневые поля

| Поле | Тип | Обязат. | Описание |
|------|-----|---------|----------|
| `format` | string | да | `"polimuli/pol"` — маркер формата |
| `version` | number | да | `1` — версия схемы |
| `meta` | object | да | метаданные (см. ниже) |
| `canvas` | object | да | размеры холста `{w,h}` |
| `style` | object | нет | глобальные умолчания (опции HUD, подпись) |
| `acts` | array | да | сцены-акты с таймингом и текстом (≥1) |
| `actors` | array | нет | персонажи-эмодзи и их поведение |
| `particles` | array | нет | источники частиц-эмодзи |

### 2.1. `meta`

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | короткий номер/слаг (например `"16"`) |
| `title` | string | название эпизода |
| `genre` | string | жанр (подсказка для стиля) |
| `dur` | number | длительность в секундах (такты — секунды) |
| `loop` | boolean | по умолчанию `true` — зациклить |
| `emojis` | array | словарь-подпись «эмодзи-направление» (для справки) |

### 2.2. `style`

| Поле | Описание |
|------|----------|
| `hud.labelColor` | цвет подписи HUD |
| `hud.barColor` | цвет прогресс-бара |
| `caption.font` | размер шрифта заголовка-акта (px) |
| `caption.color` | цвет текста акта |
| `caption.shadow` | цвет тени текста |
| `board.x`,`board.y` | угол доски для конспекта (пиксели) |
| `board.w`,`board.h` | размер доски (пиксели) |
| `board.bg` | цвет «полотна» доски |
| `board.frame` | цвет рамки доски |
| `board.text` | цвет «мела» на доске (по умолчанию для строк) |
| `board.font` | размер шрифта строк доски (px) |
| `board.step` | интервал появления строки доски (сек, умолч. 1.4) |
| `board.title` | заголовок-шапка доски (тема лекции, рисуется при помощи `titleColor`) |
| `board.titleColor` | цвет заголовка доски (по умолчанию `#e8cf9a`) |
| `board.rowH` | шаг строки доски (px, по умолчанию 34) |
| `board.pen` | эмодзи пишущей руки/мела (по умолчанию `✍️`) |
| `board.rep` | эмодзи представителя/аватара лектора у доски (пусто — выкл) |
| `board.repSize` | размер представителя (px, по умолчанию 44) |

## 3. Акты (`acts`)

Акты — сцены эпизода. Сортировка по `at` (по возрастанию).

| Поле | Тип | Описание |
|------|-----|----------|
| `at` | number | время старта акта, сек (первый обычно `0`) |
| `text` | string | подпись-заголовок акта (показывается сверху) |
| `bg` | object | ключ-цвета фона `{top,bottom}` — градиент акта |
| `board` | array | доска конспекта — см. раздел 3.1 «Живая доска» |

Между актами фон плавно перетекает (интерполяция цвета по времени).
Если `bg` у акта не задан — фон остаётся предыдущим.

### 3.1. Доска конспекта (`acts[].board`) — «живая доска»

Доска для лекции: лектор-профессор набрасывает материал, и строки
«пишутся мелом» одна за другой. Глобальная геометрия — в `style.board`;
контент — в акте.

**Правило непустой доски (искусство подачи).** Доска — это
пространство смысла, а не пустая рамка. Последовательные строки-строки
**заполняют доску сверху вниз**, каждая занимает своё место
(`rowH` px вниз). Доска читается как лист: сверху — шапка-тема
(`style.board.title`), ниже — тезисы, схемы и итоги. Пустоты оформляются
плашками-ролями, поэтому «вода» (плавное запоминание) не превращается
в пустоту.

Два вида элементов доски:

**a) Короткая строка (простой режим):**

```json
"acts": [
  { "at": 0, "text": "КУРС — ЛЕКЦИЯ НА 1.5 ЧАСА",
    "board": ["КУРС = ОДНА ИДЕЯ", "ФОРМАТ: ЛЕКЦИЯ 1.5 Ч"] }
]
```

**б) Объект-блок с ролью (живой режим):**

```json
"style": { "board": { "x": 600, "y": 120, "w": 330, "h": 300,
                       "bg": "#2e4632", "frame": "#8a5a2a",
                       "font": 18, "step": 1.6, "title": "ЛЕКЦИЯ 1" } },
"acts": [
  { "at": 0, "text": "УНИВЕРСИТЕТ · ЭМБЛЕМА", "board": [
      { "t": "КОДЕКС = СВОБОДА И ЦЕЛИ", "role": "thesis" },
      { "t": "НЕВЕЖДЫ → ОБРАЗОВАННЫЕ",  "role": "diagram" },
      { "t": "ТЕМП ×0.25…×16 · ПАУЗА · ПОВТОР", "role": "note", "indent": 10 },
      { "t": "ИТОГ: ДОСКА ЖИВЁТ",       "role": "result" }
  ]}
]
```

Поля объект-блока:

| Поле | Описание |
|------|----------|
| `t` | текст строки |
| `role` | роль-плашка подсветки: `thesis` (тезис), `diagram` (схема), `result` (итог), `note` (заметка, по умолчанию) |
| `color` | свой цвет строки (перекрывает цвет роли) |
| `indent` | левый отступ (px) — для схем и вложенности |
| `font` | свой размер шрифта (px) |

Роли рисуются плашкой-подсветкой и маркером слева (`▪` тезис, `·`
схема, `▸` итог), поэтому доска не выглядит пустой даже между
строками.

**Тайминг доски.** Строка `i` начинает писаться при
`t >= act.at + i * board.step` и **пишется от руки слева направо**
в окне `board.step` (не появляется мгновенно).

**Принцип «живого учителя» (никаких бездушных фотороботов).** Доска
меловая, и пишет её человек, а не типографский вывод:
- строка рендерится **мелом** — шероховатый зернистый след (несколько
  полупрозрачных наложений + меловые точки), как настоящий мел;
- **пишущая рука** `board.pen` (✍️) ведёт мел по строке, из-под руки
  летит **меловая крошка** — виден труд;
- **представитель** `board.rep` (аватар лектора) виден у доски во время
  письма: он стоит у пишущей строки, наклоняется к доске и ведёт
  рукой-мелом — живой учитель, который старается, а не картинка.

Ролевые плашки (`thesis`/`diagram`/`result`/`note`) заполняют пустоты,
поэтому доска не выглядит пустой между строками — «вода» подачи
не превращается в пустоту.

## 4. Акторы (`actors`)

Персонажи эпизода. Поля:

| Поле | Тип | Описание |
|------|-----|----------|
| `id` | string | имя актора (для `particles.from` и `key`) |
| `emoji` | string | эмодзи-спрайт персонажа |
| `x`,`y` | number | базовая позиция (центр) |
| `size` | number | размер эмодзи (px высоты) |
| `bob` | object | вертикальное покачивание `{amp, speed}` |
| `sway` | object | горизонтальное колебание `{amp, speed}` |
| `pulse` | object | пульсация размера `{amp, speed}` |
| `cycle` | object | смена эмодзи `{emojis:[...], period}` |
| `key` | array | таймлайн-ключи движения |
| `acts` | object | псевдоним `key` (альтернативное имя поля) |
| `visible` | boolean/object | видимость: `true`/`false` или `{from,to}` |

### 4.1. Ключи (`key`)

Линейная интерполяция между ключами по времени:

```json
"key": [
  { "at": 0, "x": 100, "y": 300, "size": 80 },
  { "at": 6, "x": 700, "size": 100 }
]
```

Недостающие компоненты наследуются от предыдущего ключа/базового значения.
Интерполяция линейная (простой, предсказуемый формат).

### 4.2. Циклы эмодзи

```json
"cycle": { "emojis": ["☀️","⛅","🌧️"], "period": 4 }
```

Актор меняет эмодзи каждые `period` секунд по кругу. Полезно для погоды,
светофоров, смен состояний.

---

## 5. Частицы (`particles`)

Источники эмодзи-частиц (дым, искры, пузыри, звёзды).

| Поле | Тип | Описание |
|------|-----|----------|
| `from` | string | (опц.) id актора — начало у его позиции |
| `x`,`y` | number | (опц.) фиксированная точка, если `from` нет |
| `dx`,`dy` | number | смещение от точки/актора |
| `emoji` | string | эмодзи частицы |
| `rate` | number | вероятность спавна за секунду (0..1+) |
| `vx`,`vy` | number | начальная скорость |
| `life` | number | время жизни, сек |
| `size` | number | размер |
| `gravity` | number | гравитация (по умолчанию 0) |
| `alpha` | number | прозрачность 0..1 (по умолчанию 1) |
| `count` | number | (опц.) фиксированный выброс N частиц разово в акте `atHere`? — нет: только вероятностный поток |

Только поток: каждая дефиниция спавнит максимум одну частицу за кадр,
если `Math.random() < rate * dt`.

## 6. Контракт воспроизведения

Плеер обязан:

1. Прочитать `meta.dur` и `canvas`.
2. Каждый кадр: `t = (now - start) / 1000`; если `t > dur` и `meta.loop !== false`
   — `t = t % dur`.
3. Нарисовать фон-градиент акта с перетеканием между соседними `acts`.
4. Нарисовать акторов в порядке массива (эмодзи-спрайты поверх фона).
5. Спавнить частицы, обновлять и рисовать их.
6. Показывать текст текущего акта (последний `acts.at <= t`).
7. Если у `acts` есть `board` — рисовать доску (`style.board`) и строки
   «мелом» по накопительному таймингу `board.step`.
8. Рисовать HUD: подпись + прогресс-бар `t / dur`.
9. Поддерживать паузу/прокрутку времени по канвасу (клик = пауза,
   shift+клик = сброс) — опциональный UX плеера.

Упаковщик обязан:

1. Проверить формат по схеме (валидация полей, типов, ссылок `from`→`id`,
   ключей внутри `dur`).
2. Собрать самодостаточный `.html`: движок + рантайм + данные одним файлом,
   без внешних запросов (работает из `file://`).
3. Сообщать номер ошибок и предупреждений (код выхода: 0 — ok, 1 — warn,
   2 — error).

## 7. Правила полиарт-стиля для данных

- Эмодзи — структурные элементы, а не декорация: замени словарь — получишь
  другой визуальный язык (принцип «один мульт = один словарь»).
- Палитра фона — 2 ключа на акт; минимум света, максимум читаемости.
- Акторы — как спрайты на «кукольной сцене»: позиция + покачивание.
- Никаких текстовых образов внутри данных — только значения; язык и
  комментарии только в `meta.title`/`acts.text`.
